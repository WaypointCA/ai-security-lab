# Contributing to AI Security Lab

Thank you for your interest in contributing to the AI Security Lab! This project aims to provide a comprehensive, free learning path for AI security professionals.

## How to Contribute

### Reporting Issues

- **Broken Links**: If you find a link that no longer works, please open an issue with the section name and the broken URL.
- **Outdated Information**: AI security moves fast. If you notice outdated tools, techniques, or resources, let us know.
- **Bugs in Scripts**: If any of the setup scripts don't work on your system, please include your OS version and error messages.

### Suggesting Improvements

- **New Resources**: Found a great free course, tool, or paper? Open an issue or PR to add it.
- **Better Explanations**: If something is unclear, suggest improvements.
- **New Phases or Topics**: If there's a critical AI security topic we've missed, propose it.

### Submitting Pull Requests

1. **Fork the repository**
2. **Create a feature branch**: `git checkout -b feature/add-new-resource`
3. **Make your changes**
4. **Test your changes**: Ensure links work and scripts run
5. **Commit with clear messages**: `git commit -m "Add XYZ tool to Phase 2 resources"`
6. **Push to your fork**: `git push origin feature/add-new-resource`
7. **Open a Pull Request**

### What We're Looking For

**High-value contributions:**
- Free, high-quality learning resources
- Working lab exercises with clear instructions
- Tools that are actively maintained
- Research papers that are foundational or cutting-edge
- Scripts that work across Ubuntu/Kubuntu 24.04+

**Please avoid:**
- Paid resources (unless there's a substantial free tier)
- Proprietary tools without free alternatives
- Resources behind paywalls or requiring corporate accounts
- Outdated tools that are no longer maintained

### Content Guidelines

**For new resources:**
- Must be freely accessible (or have a meaningful free tier)
- Should be from reputable sources
- Include a brief description of why it's valuable
- Place in the appropriate phase/section

**For lab exercises:**
- Must work in the standard environment (Ubuntu 24.04 + Python venv)
- Include clear setup instructions
- Document expected outcomes
- Note any additional dependencies

**For scripts:**
- Must be POSIX-compliant or clearly marked as bash-specific
- Include error handling
- Add comments for non-obvious steps
- Test on a fresh Ubuntu 24.04 install if possible

### Code of Conduct

- Be respectful and constructive
- Focus on the educational mission
- Help newcomers learn
- Credit original sources
- Follow responsible disclosure for any vulnerabilities you find

### Questions?

Open an issue with the `question` label, and we'll do our best to help.

Contributors will be recognized in our README. Significant contributions may be highlighted in blog posts or social media.

Thank you for helping make AI security education accessible to everyone!
